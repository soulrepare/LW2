## 2. Команди проєкту

| Команда | Що робить |
|---|---|
| `npm install` | Встановлює залежності розробки (`devDependencies`: `sass`) у `node_modules` та створює `package-lock.json`. |
| `npm run scss:build` | Одноразово компілює `src/scss/main.scss` у стиснутий файл `css/style.css` (`--no-source-map --style=compressed`). |
| `npm run scss:watch` | Запускає компілятор Sass у режимі відстеження (`--watch`) — автоматично перекомпільовує CSS при збереженні файлів SCSS. |
| `npm run build:cards` | Запускає `scripts/build-cards.js`: зчитує `data/products.json` засобами модуля `fs` і генерує картки в `index.html` між маркерами. |
| `npm run build` | Повний цикл збирання: виконує `npm run build:cards && npm run scss:build`. |

### Збирання проєкту у чистій копії:
```bash
git clone https://github.com/<логін>/<репозиторій>.git
cd <репозиторій>
```

## 4. Вибір модульної системи (CommonJS vs ESM)

У скрипті `scripts/build-cards.js` використано модульну систему **CommonJS** (`const fs = require('fs');`):
- **Причина вибору:** CommonJS є рідною та перевіреною модульною системою Node.js за замовчуванням, яка працює «з коробки» без додавання `"type": "module"` у `package.json`, не вимагає вказувати розширення при відносних імпортах і забезпечує максимальну сумісність з будь-якими версіями Node.js.
- **Як перемкнути на ESM:**
  1. Додати в `package.json` поле `"type": "module"`.
  2. У `scripts/build-cards.js` замінити `require` на:
     ```js
     import fs from 'node:fs';
     import path from 'node:path';
     ```

## 5. Обробка помилок у `build-cards.js`

Скрипт захищений від аварійного падіння з розкриттям системного стека Node.js:
- Якщо файл `data/products.json` відсутній або перейменований — скрипт виводить зрозуміле повідомлення `[build-cards] Помилка: не знайдено або не вдалося прочитати файл...` і завершує роботу з кодом `process.exit(1)`.
- Якщо JSON пошкоджений (наприклад, синтаксична помилка або зайва кома) — блок `try/catch` перехоплює виняток і виводить читабельне пояснення помилки без трейсу стека.
- Якщо в `index.html` видалено або пошкоджено маркери `<!-- cards:start -->` чи `<!-- cards:end -->` — скрипт попереджає про це й не руйнує розмітку сторінки.

## 6. Відповіді на контрольні питання (до захисту)

1. **Що зберігає package.json і які поля в ньому обовʼязкові?**  
   Зберігає метадані проєкту, список залежностей, скрипти автоматизації та конфігурацію. Обов'язковими для публікації є `name` та `version`.

2. **Чим dependencies відрізняються від devDependencies і чому sass належить до других?**  
   `dependencies` потрібні для роботи додатку в runtime (у браузері/на сервері), а `devDependencies` — лише під час розробки та збирання. `sass` потрібен тільки для компіляції SCSS у CSS на етапі збирання; у браузері Sass не виконується, тому він встановлений у `devDependencies`.

3. **Навіщо потрібен package-lock.json і що станеться без нього в іншого розробника?**  
   Фіксує точні версії всіх транзитивних залежностей і хеші цілісності. Без нього інший розробник при `npm install` може отримати новіші мінорні або патч-версії пакетів, що потенційно призведе до несподіваних багів через несумісність.

4. **Що робить npm install без аргументів і звідки він бере перелік пакетів?**  
   Зчитує `package.json` та `package-lock.json`, завантажує зазначені пакети та розгортає їх у локальну папку `node_modules`.

5. **Чому node_modules не зберігають у репозиторії?**  
   Папка має величезний обсяг (тисячі дрібних файлів), засмічує історію git і може містити платформно-залежні бінарні збірки під конкретну ОС. Її завжди можна швидко згенерувати командою `npm install`.

6. **Як працює npm run і де npm шукає виконуваний файл пакета?**  
   Шукає однойменний скрипт у секції `"scripts"` у `package.json`, тимчасово додає локальну директорію `node_modules/.bin` до системного `PATH` і виконує команду.

7. **Що означають символи ^ і ~ у версії пакета?**  
   `^1.89.0` (карет) дозволяє оновлення мінорних і патч-версій (>= 1.89.0 і < 2.0.0).  
   `~1.89.0` (тильда) дозволяє оновлення лише патч-версій (>= 1.89.0 і < 1.90.0).

8. **Різниця між require у CommonJS та import у ESM, як перемкнути проєкт на ESM?**  
   `require` є синхронним динамічним імпортом часу виконання; `import` підтримує статичний аналіз, tree-shaking та асинхронне завантаження. Для перемикання додають `"type": "module"` у `package.json` і використовують синтаксис `import ... from ...`.

9. **Що робить препроцесор Sass і чому браузеру потрібен саме зібраний CSS?**  
   Sass розширює мову CSS змінними, вкладеністю, міксинами та функціями, компілюючи їх у стандартний чистий CSS. Браузерні рушії не розуміють синтаксис Sass і можуть парсити лише стандартизовані CSS-файли.

10. **Які переваги дає винесення даних карток у JSON порівняно з розміткою вручну?**  
    Розділення даних і представлення (separation of concerns), легкість додавання нових товарів без ризику поламати HTML-верстку, усунення дублювання коду, можливість отримувати ті самі дані з бекенду або API.
